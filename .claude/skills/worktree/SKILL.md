# worktree — 作業ツリーを切り、終わったら安全に片付ける

**実装は作業ツリーで行う。** 片付けは「マージ済みを確かめてから消す」を機械で守る。

実体は `scripts/wt.sh`。確認の手順を散文で追わせず、スクリプトに持たせてある(確認の取りこぼしがそのまま作業の消失になるため)。

```text
bash .claude/skills/worktree/scripts/wt.sh create <branch>
bash .claude/skills/worktree/scripts/wt.sh list
bash .claude/skills/worktree/scripts/wt.sh cleanup [--dry-run] <branch>
```

どこから呼んでも主作業ツリーで動く。依存は `git`・`jq`・`gh`(`list` と `cleanup`)。

## 作る

**実装に着手するときは、必ず作業ツリーを切る。** 主作業ツリーでブランチを切り替えて実装しない——並行する作業や子セッションと作業ツリーを取り合うため。

1. `wt.sh create <branch>` を実行する。ブランチ名はプロジェクトの規約に従う
   - 起点は**リモートの既定ブランチの最新**(実行時に fetch する)。手元の既定ブランチが古くても引きずられない
   - 置き場は `.claude/worktrees/<branch>`(git 管理外にしておく)
   - 追跡先は持たせない。最初の push は `git push -u origin <branch>` で行う
   - `.envrc` があり `direnv` が入っていれば `direnv allow` まで済ませる
2. 依存の導入・ポートのずらし・git 管理外の設定ファイル(`.env` 類)の用意は、**プロジェクトの `CLAUDE.md` に従う**。スクリプトはここに踏み込まない
3. 以後の作業はその作業ツリーの中で行う(子セッションへ出すなら、そのパスを渡す)

実装以外の作業(文書だけの小さな変更など)をどこで行うかは、プロジェクトの `CLAUDE.md` に従う。

## 片付ける

**PR がマージされたら、同じ流れの中で片付ける。** 残すと、次に同じ名前で切れない・古い作業ツリーで作業を再開してしまう、といった事故の元になる。

1. 作業ツリーの中で動いているもの(開発サーバ・子セッション)を止める。主作業ツリーで対象ブランチを使っていたなら、既定ブランチへ切り替える(主作業ツリーは消さず、ブランチだけを片付ける)
2. 主作業ツリーへ戻り、`wt.sh cleanup --dry-run <branch>` で確認結果と消すものを見る
3. すべて `ok` なら `wt.sh cleanup <branch>` を実行する
4. 既定ブランチを pull する

`NG` が出たら**何も消えていない**。原因を直すか、判断が要るものはユーザーへ返す。**ユーザーの判断なしに、確認を迂回して手で消さない**(`git worktree remove --force` や、確認なしの `git branch -D` を使わない)。

### 後始末の安全確認

`cleanup` は次をすべて確かめ、1つでも落ちたら何も消さずに止まる。

| 確認 | 守っているもの |
| --- | --- |
| そのブランチから作られた**マージ済みの PR** がある | 未マージの作業 |
| ローカルブランチの先端が PR の先端に含まれる | マージ後に足したコミット |
| リモートブランチの先端が PR の先端に含まれる | マージ後に他所から push されたコミット |
| 作業ツリーに未コミットの変更・未追跡ファイルが無い | コミットし忘れ |
| 作業ツリーの中を作業ディレクトリにしているプロセスが無い | 動いている開発サーバ・子セッション |
| 対象の作業ツリーの中から呼ばれていない | 自分の足場 |
| 主作業ツリーが対象ブランチのままではない | 主作業ツリー(消す対象にしない) |
| 既定ブランチではない | 既定ブランチ |

確認を通ったら、作業ツリー → ローカルブランチ → リモートブランチの順に消す。**どれも「確認した時点のまま」のときだけ消す**——確認から削除までの間に入った変更を消さないため。

- 作業ツリーは `--force` なしで消す。確認の後に変更が入っていれば git 自身が止める。**無視ファイル(`node_modules` など)は一緒に消える**
- ローカルブランチは、先端が確認時の値と一致するときだけ消す(`git update-ref -d <ref> <確認時の先端>`)。squash マージではブランチが既定ブランチの祖先にならず、`git branch -d` が通らないため
- リモートブランチも、先端が確認時の値と一致するときだけ消す(`--force-with-lease` つきの削除)。マージ時に消えていれば(`gh pr merge --delete-branch`)何もしない

既定ブランチが分からない(`origin/HEAD` が無い)ときは、推測せずに止まる。`git remote set-head origin --auto` で設定してから実行し直す。

### マージされずに終わったブランチ

PR を閉じた・方針が変わった、などマージされなかったブランチは `cleanup` が消さない。**消すかどうかはユーザーの判断**なので、未マージのコミットを示して確認を取ってから手で消す。

## 一覧

`wt.sh list` で、ローカル・リモートのブランチと PR の状態、作業ツリーの所在を並べる。**片付け忘れ(`MERGED` なのに残っているもの)を探すときに使う。**

## やらないこと

- 主作業ツリーで実装する
- 確認に落ちたブランチや作業ツリーを、ユーザーの判断なしに `--force` や手のコマンドで消す
- 子セッションに片付けをさせる(作業ツリーの中にいるので消せない。片付けは主作業ツリーから行う)
