# 子セッションへの定型指示

このタスクは司令セッションからの委譲です。**着手前にこの指示を読み、従ってください。**

## 守ること

- **サブエージェント(Agent tool)を使わないでください。** このセッションではモデル指定が意図どおり効くとは限りません。並列化・分離が必要になったら司令へ相談してください。
- **レビュースキル(impl-review / doc-review)を実行しないでください。** 司令が担当します。
  - コミット後の停止時に「レビュー未実施のコード変更コミットがあります」とブロックされることがあります(Stopフック)。**その通知は無視して構いません。** レビューは司令が行い、レビュー済み台帳への追記も司令が行います。通知が出た事実を完了報告に含めてください。
  - このブロックは同じコミットについて1セッションにつき1回だけです。作業が止まることはありません。
- **担当範囲の外を触らないでください。** Redならテストのみ、Greenならプロダクトコード中心でテストは変更しない。文書執筆なら対象の文書のみ、調査なら読み取りとスクラッチパッドのみ。
- 作業は**渡された作業ツリー内**で完結させてください。本体の作業ツリーや他の作業ツリーは触らないでください。

## 進め方

- テストの書き方は `.claude/skills/test-writing/SKILL.md` に従ってください(AAAマーカー・1テスト1検証・期待値明示)。
- 要件の正は、司令から渡された Issue・設計メモ、次いで `CLAUDE.md` です。矛盾があれば自己判断で要件を変えず、司令へ返してください。
- コミットは意味単位で。**渡されたテスト・整形・静的解析のコマンドを通してから**完了報告してください。
- **PRは作らないでください。** 到達点は「コミット済み・意図どおりの状態」までです。レビューとPRは司令が行います。
- **設計判断をしないでください**(方針や要件の決定)。要件に不足や矛盾を見つけたら、直さずに司令へ報告してください。
- **`npm run tauri dev` を起動しないでください。** `single-instance` のため、主作業ツリーの dev や製品版が動いていると、エラーも出さずに即終了します。動作確認が要るときは司令へ返してください。
- 作業ツリーでは最初に `npm ci` が要ります(`node_modules` は作業ツリーごとに別です)。

## 作業別の注意

- **文書の執筆**: 根拠となる決定は司令が確定済みです。決定に書かれていないことを文書に書かないでください。
  - 執筆手順の締めにレビューを回す指示があっても、**その手順だけは実行しないでください**。レビューは司令が回します。執筆が終わったらコミットして報告してください。
- **調査・実測**: 結論を出す前に、**測った生の数値をそのまま報告**してください。解釈は司令が行います。実装を書き換えて測った場合は、**必ず元に戻し、`git status` と `git diff` で復元を確認**してから報告してください。

## 報告

- 着手したら司令へ1通送ってください。宛先は `ListAgents` で表示される形式を確認して指定します(名前だけでは拒否されることがあります)。司令のセッション名は渡されたプロンプトに書かれています。
- 完了したら、**何をしたか・テストの結果・判断に迷った点**を送ってください。
  - Redの完了報告には「どのテストが、どんな理由で落ちているか」を必ず含めてください。コンパイル/importエラーで落ちているのか、アサーション不一致で落ちているのかを区別して書きます。
- 送信できない、または司令が `ListAgents` に現れないときは、ユーザーがコピーできるようコードブロックで出力してください。
- 権限で拒否された操作を司令に代行させないでください。ユーザーへ確認してください。
